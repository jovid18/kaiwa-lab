# 약점 복습

입력: `$ARGUMENTS`

## 핵심 개념: 패턴 단위 복습

개별 문장이 아닌 **패턴**(조사 누락/오용, 유사어 혼동 등)을 복습 단위로 삼는다.
한 패턴에서 대표 문장 2-3개를 출제하고, 전부 맞추면 패턴 전체가 통과된다.

## 동작 흐름

### 1단계: 복습 패턴 선정

1. `review/state.json`을 읽어 패턴별 복습 이력을 파악한다.
2. `$ARGUMENTS`에 따라 대상 범위를 결정한다:
   - `grammar`: `weakness/grammar.md`의 패턴만
   - `vocabulary`: `weakness/vocabulary.md`의 패턴만
   - `expression`: `weakness/expression.md`의 패턴만
   - `all` 또는 비어 있음: 전체 패턴
3. 복습 대상 패턴 우선순위:
   - **1순위**: 이전 복습에서 실패한 패턴 (`pass: false`)
   - **2순위**: 아직 한 번도 복습하지 않은 패턴
   - **3순위**: 통과했지만 복습 간격이 도래한 패턴
4. 우선순위 내에서는 횟수가 많은 패턴(🔴 > 🟡)을 우선한다.
5. 한 세션에 **5개 패턴**을 선정한다.

### 2단계: 대표 문장 선정

각 패턴에서 **5개 문장**을 선정한다.

선정 우선순위:

1. **이전 세션에서 틀린 문장** (반드시 포함)
2. **아직 출제된 적 없는 문장**
3. **이전에 맞췄던 문장** — pass 날짜가 오래된 순 (큐 방식)

추가 규칙:

- 한글 원문이 있는 항목만 선정
- 같은 설명(같은 종류의 실수)이 반복되면 대표 1개만 선정하고, 다양한 하위 유형을 커버하도록 분산

### 2-1단계: weakness ↔ state.json ↔ progress.md 동기화

HTML 생성 전에 `weakness/*.md`와 `review/state.json`을 대조하여 동기화한다.

1. **새 패턴 발견**: weakness에 존재하지만 state.json에 없는 패턴 → state.json에 빈 항목 추가 (미복습 상태)
2. **졸업 패턴 재활성화**: state.json에서 `graduated: true`인 패턴의 weakness 테이블 행 수가 `sentences`에 기록된 수보다 많으면 → 새 실수가 추가된 것 → `graduated: false`로 변경 + `next_review`를 오늘로 설정
3. **progress.md 갱신**: weakness의 실제 문장 수, state.json의 pass 문장 수, 졸업 여부를 반영하여 progress.md를 갱신한다.

### 3단계: HTML 파일 생성

`review/session.html` 파일을 생성한다. 이 파일에 출제 데이터와 채점 로직을 모두 포함한다.

#### HTML 구조

```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>복습</title>
    <style>
      /* 스타일 */
    </style>
  </head>
  <body>
    <!-- 한 문장씩 표시하는 카드 UI -->
    <!-- 입력 필드 + 다음 버튼 -->
    <!-- 마지막: 전체 채점 결과 + 결과 복사 버튼 -->
    <script>
      const questions = [
        /* 출제 데이터 */
      ];
      // 채점 로직, UI 로직, 결과 코드 생성
    </script>
  </body>
</html>
```

#### HTML UI 흐름

1. **출제 화면**: 전체 문장을 한 페이지에 나열
   - 각 문장은 카드 형태로 표시
   - 한글 원문 전체를 보여주되, 이전에 틀렸던 부분을 `<strong>` 태그로 강조
   - 각 카드 아래에 입력 필드 (볼드 부분의 일본어를 입력)
   - **패턴명, 카테고리, 출처는 보여주지 않는다**
   - 문장 순서는 패턴별로 묶지 않고 **랜덤하게 섞는다**
   - 맨 아래 **"채점" 버튼**

2. **채점 화면**: "채점" 버튼 클릭 후 같은 페이지에서 결과를 표시
   - 각 카드에 ✅/❌ 표시 추가
   - 틀린 경우: 사용자 답안 + 정답 + 설명 표시
   - 맞은 경우: 간단히 ✅만 표시
   - 페이지 상단에 패턴별 종합 결과 표시
   - 맨 아래: **"결과 복사" 버튼** — 클릭 시 결과 JSON을 클립보드에 복사, "복사됨!" 텍스트로 변경

#### questions 데이터 구조

```javascript
const questions = [
  {
    id: 1,
    korean: '확실히 사람이 <strong>많지 않아서</strong> 한산하군',
    boldText: '많지 않아서',
    answer: '多くなくて',
    wrong: '多くじゃなくて',
    explanation: 'い형용사 부정은 「くない」',
    pattern: 'grammar:동사 활용형 오류',
  },
  // ...
];
```

#### 결과 JSON 형식

"결과 복사" 버튼 클릭 시 클립보드에 복사되는 JSON:

```json
{
  "date": "2026-03-25",
  "results": {
    "grammar:조사 누락/오용": {
      "sentences": {
        "03-24:友達ように": { "input": "友達のように", "answer": "友達のように", "pass": true },
        "03-25:8時50分に": { "input": "8時50分ごろに", "answer": "8時50分ごろに", "pass": true },
        "03-20:お腹空いて": { "input": "お腹空いて", "answer": "お腹が空いて", "pass": false }
      }
    },
    "vocabulary:유사어 혼동": {
      "sentences": {
        "03-25:評判": { "input": "評価", "answer": "評価", "pass": true },
        "03-24:詰まれば": { "input": "溜まれば", "answer": "溜まったら", "pass": false }
      }
    }
  }
}
```

- 각 문장에 `input`(사용자 입력), `answer`(정답), `pass`(HTML 채점 결과)를 포함한다.
- HTML 채점은 **완전 일치** 기준으로 엄격하게 판정한다 (공백/전각반각 차이만 무시).

#### 채점 기준 (HTML 내 JavaScript)

- 사용자 입력과 `answer`를 비교한다.
- **완전 일치**면 ✅
- 불일치면 ❌
- 공백, 전각/반각 차이는 무시한다.

### 4단계: 브라우저에서 열기

`open review/session.html` 명령으로 브라우저에서 HTML 파일을 연다.

사용자에게 안내:

```
복습 세션을 브라우저에서 열었습니다.
완료 후 결과를 복사해서 여기에 붙여넣어 주세요.
```

### 5단계: 결과 반영 (CLI 재채점)

사용자가 결과 JSON을 CLI에 붙여넣으면:

1. JSON을 파싱한다.
2. HTML에서 `pass: false`인 문장의 `input`과 `answer`를 재검토한다.
   - 이전 실수 포인트가 교정되었고, 문법적으로 정확하고 자연스러운 표현이면 **pass로 변경**한다.
   - 예: 정답 「溜まったら」, 입력 「溜まれば」 → 이전 실수(詰まれば→溜まる)의 핵심인 어휘 선택은 교정됨 → pass
3. 재채점으로 변경된 항목이 있으면 사용자에게 보여준다:
   ```
   ### 재채점
   - Q5: 「溜まれば」→ 이전 실수(詰まれば)는 교정됨 → ✅로 변경
   ```
4. 최종 결과로 `review/state.json`을 업데이트한다.
5. `review/progress.md`를 갱신한다 (진행 수, 상태).
6. `review/session.html`을 삭제한다.
7. CLI에 세션 요약을 표시한다.

## state.json 구조

```json
{
  "patterns": {
    "grammar:조사 누락/오용": {
      "reviews": [{ "date": "2026-03-25", "pass": false, "questions": 3, "correct": 2 }],
      "next_review": "2026-03-26",
      "graduated": false,
      "sentences": {
        "03-24:友達ように": { "status": "pass", "date": "2026-03-25" },
        "03-25:8時50分に": { "status": "pass", "date": "2026-03-25" },
        "03-20:お腹空いて": { "status": "fail", "date": "2026-03-25" }
      }
    }
  },
  "version": 2
}
```

### 키 형식

**패턴 키**: `{파일}:{패턴명}`

- 파일: `grammar`, `vocabulary`, `expression`
- 패턴명: 섹션 이름 (예: `조사 누락/오용`, `유사어 혼동`)

**문장 키**: `{날짜}:{틀린 표현}`

- `sentences` 안에서 각 문장의 최근 결과를 추적한다.
- `"pass"`: 이전 세션에서 맞춤 → 다음 선정에서 후순위
- `"fail"`: 이전 세션에서 틀림 → 다음 선정에서 반드시 포함

### 복습 간격

- 첫 통과 → 3일 후 복습
- 두 번째 통과 → 7일 후 복습
- 세 번째 통과 → 졸업 (`graduated: true`)
- 실패 → 다음날 복습
- 실패 시 연속 통과 카운트 리셋

### 졸업 조건

- 3회 연속 통과하면 졸업한다.
- 졸업한 패턴은 복습 대상에서 제외된다.
- 졸업 후에도 해당 패턴에 새로운 실수가 추가되면 (weakness 테이블에 새 행이 생기면), 졸업이 해제되고 다시 복습 대상에 포함된다.

## 세션 요약

결과 반영 후 CLI에 표시:

```
## 복습 결과

| 패턴 | 결과 | 정답률 |
|------|------|--------|
| 조사 누락/오용 | ✅ 통과 | 3/3 |
| 유사어 혼동 | ❌ 재복습 | 1/2 |
| 동사 활용형 오류 | ✅ 통과 | 2/2 |

### 다음 복습 예정
- 내일: 유사어 혼동
- 3일 후: 조사 누락/오용, 동사 활용형 오류
```

## 규칙

1. 복습 대상이 없으면 "오늘 복습할 패턴이 없습니다"를 표시하고 중단한다.
2. 한글 원문이 없는 항목은 출제 대상에서 제외한다.
3. 설명은 한국어로 작성한다.
4. `review/state.json` 파일이 없거나 비어 있으면 초기화한다.
5. 대표 문장 선정 시 이전에 출제한 문장은 피하고, 매 세션마다 다른 문장을 선정한다.
6. HTML 파일 생성 시 외부 라이브러리 없이 순수 HTML/CSS/JS만 사용한다.
7. HTML의 스타일은 깔끔하고 모바일에서도 사용 가능하게 반응형으로 만든다.

# note-proofread

`note-pull` **직후**, 방금 내려받은 `diary/YYYY-MM-DD.md`를 자연스러운 일본어로 다듬는 스킬.

핵심은 **git staging을 diff 리뷰 장치로 쓰는 것**이다. 원본(pull본)을 index에 고정한 뒤 working tree만
교정하면, `git diff`가 곧 "제안한 교정분"이 된다. 사용자는 `-`(원문)/`+`(교정)을 나란히 보며 공부한다.

> ⚠ 이 스킬은 **교정 제안까지만.** 교정본을 확정하거나 note에 반영하지 않는다. 사용자가 diff를 보고
> **note 웹 에디터에서 직접 수정**한 뒤, `/note-pull --force`로 최종본을 재pull하는 것이 다음 단계다.
> 따라서 working tree의 교정본은 재pull 시 덮어써진다 — 그래도 된다. 교정의 목적은 학습 자료 제공이다.

## 절차

1. **대상 파일 확인.** 사용자가 준 경로(없으면 방금 pull한 `diary/YYYY-MM-DD.md`)를 Read.
   frontmatter가 있는 note md인지 확인한다. 아니면 사용자에게 되묻는다.

2. **원본을 stage에 고정.** 교정을 시작하기 전에 현재(=pull된) 내용을 index에 넣는다:

   ```bash
   git add diary/YYYY-MM-DD.md
   ```

   - 이 stage된 버전이 diff의 비교 기준(원본)이 된다. **교정 편집보다 반드시 먼저** 실행할 것.

3. **본문만 교정.** frontmatter, 이미지(`![](...)`), 링크의 URL은 **그대로 둔다.** 본문 텍스트만:
   - **한글로 쓴 문장은 일본어로 번역해 치환한다.** 한글을 남겨두고 일본어를 덧붙이는 것이 아니라,
     그 자리를 번역문으로 **대체**한다 (원문 한글은 diff의 `-`쪽에만 남는다). 일기 전체가 한글이어도
     마찬가지 — 전부 번역한 뒤, 아래 항목들을 그 번역문에 그대로 적용한다.
     문단 순서와 이미지 삽입 위치는 원문 그대로 유지한다.
   - **문법/조사/활용/오타를 자연스러운 일본어로.** 예: `同録`→`登録`, `飲みますた`→`飲みました`,
     `調べたには`→`調べたところ`.
   - **문장·흐름 단위의 손질도 OK.** 문법적으로 틀리지 않아도 원어민이라면 그렇게 쓰지 않을 표현,
     어색한 어순, 뚝뚝 끊기는 연결은 자연스럽게 고쳐도 된다. 문장을 합치거나 나누기, 접속 표현
     추가(`それで`, `〜のに` 등), 더 자연스러운 어휘로 교체 등 전체 흐름이 매끄러워지는 수정을 환영한다.
   - **문장 끝에 가끔 적절한 이모지.** 모든 문장이 아니라 감정·소재가 뚜렷한 곳에만, 문맥에 맞게
     (예: 맥주🍺 / 영화🎬 / 책📚). 원문에 이미 있는 이모지는 유지한다. 남발 금지.
   - **의미는 보존한다.** 흐름을 다듬더라도 문장을 지우거나 새 정보(사건·감정)를 지어내지 않는다.
     일기의 사실 관계와 화자의 톤은 그대로, 표현만 원어민스럽게. 애매하면 원문 뉘앙스를 살린다.

4. **해시태그 추천.** 교정한 본문 내용을 근거로 note에 어울리는 해시태그를 5~8개 제안한다.
   - **일본어 태그**로, note에서 실제 쓰일 법한 자연스러운 것 (예: `#日記` `#東京生活` `#新宿`).
     지명·작품명·활동·감정/테마를 골고루. 왜 그 태그인지 한 줄 근거를 곁들인다.
   - frontmatter에 이미 `tags:`가 있으면(재pull 등) 중복은 제외하고 추가 후보만 제안한다.
   - **로컬 파일에는 쓰지 않는다.** 태그는 사용자가 note 웹 에디터에서 교정 반영할 때 직접 붙이고,
     재pull 시 frontmatter `tags:`로 자동으로 따라 들어온다.

5. **diff 제시 + 해설.** 교정 후:

   ```bash
   git diff diary/YYYY-MM-DD.md
   ```

   주요 수정 항목을 **문장별로 diff + 코멘트를 묶어** 한국어로 해설한다 (왜 그렇게 고쳤는지 문법 근거 포함).
   한글에서 번역해 치환한 문장은 **왜 그 어휘·표현을 골랐는지**를 해설한다
   (예: 「사주다」는 「買ってくれる」가 아니라 「おごる」, 「화이팅」은 자신에게 쓰지 않으므로 「頑張ります」).
   사용자가 note 웹 에디터에서 이 내용을 직접 반영하도록 안내한다.

6. **다음 단계 안내.** 사용자가 note에서 수정(교정 반영 + 선택한 해시태그 추가)을 마치면
   `/note-pull`(+`--force`)로 최종본을 재pull하고 `/commit`하면 된다는 것을 알려준다.
   교정·태그 제안 중 일부만 반영하는 것도 사용자의 자유다.

## 실패 대응

- **대상 파일이 애매**(경로 여러 개/없음): 방금 pull한 파일이 무엇인지 사용자에게 확인.
- **이미 다른 변경이 stage됨**: 이 파일만 재-add해도 diff 비교엔 문제 없으나, 다른 stage된 변경이
  섞여 있으면 사용자에게 알린다.
